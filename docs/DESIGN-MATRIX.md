# Design matrix (axiomatic design, Suh)

Written 2026-11-28 after Bill asked for an MIT axiomatic-design pass. Kept short on
purpose: six functions, six mechanisms, one ordering rule. Update it when a mechanism
moves; don't let it grow into a second architecture doc (ADRs and repo docs stay
authoritative for how things are built).

## Functional requirements (what the site must do, each independent)

| FR | Statement |
|----|-----------|
| FR1 Found | Rank and get cited for intent queries in Ohio and Florida. |
| FR2 Right | Editorial claims (dosing, laws, pharmacology) survive an audit. |
| FR3 Current | Feed data (strain and edible menus) is current **and valid**. |
| FR4 Return | People come back: installable tools, the email list. |
| FR5 Earn | Attention converts to affiliate clicks and, later, festival or merch revenue. |
| FR6 Know | Every change has a measurable outcome. |

Constraints, not FRs (they bound every DP and get no row): health-content framing,
no paid ads, no Reddit or Facebook as channels, no celebrity likenesses, cannabis-category
payment and ESP bans, Testing / Risk / How to revert on every change.

## Design parameters (how, as built)

| DP | Mechanism | Where |
|----|-----------|-------|
| DP1 SEO layer | Static `sitemap.xml` + `llms.txt` served by Pages, worker header hygiene, page schema, IndexNow and GSC submission | `scripts/generate-sitemap.mjs`, `scripts/git-hooks/pre-commit`, `workers/seo-proxy/src/seo-files.ts`, `scripts/indexnow-submit.py`, `scripts/gsc-submit.py` |
| DP2 Content workflow | Fact sheets, isolated auditors, cross-family (Sol) review, correctors, publishing checklist | `docs/PUBLISHING-CHECKLIST.md`, `research_notes/` |
| DP3 Feed pipeline | launchd rebuild three times a day **with the validation gate**; tool-page JSON-LD rebuilt from validated feeds | `scripts/refresh-feeds.sh`, `scripts/validate-feeds.py`, `scripts/build-tool-seo.py` |
| DP4 Retention shell | PWA (service worker, manifests, install button), D1 email capture | `sw.js`, `js/pwa-install.js`, `workers/seo-proxy/src/subscribe.ts` |
| DP5 Affiliate | `/go/` redirects inside product guides | `workers/seo-proxy/src/affiliate.ts` |
| DP6 Measurement | PostHog pull, GSC pull, weekly AI-citation test | `scripts/posthog-pull.py`, `scripts/gsc-pull.py`, `scripts/ai-citation-test.py` |

## Matrix (X = this DP materially moves this FR)

DPs in the order they must be set: Content, Feeds, SEO, Retention, Affiliate, Measurement.

| | DP2 Content | DP3 Feeds | DP1 SEO | DP4 Retention | DP5 Affiliate | DP6 Measure |
|---|---|---|---|---|---|---|
| FR2 Right | X | | | | | |
| FR3 Current | | X | | | | |
| FR1 Found | X | X | X | | | |
| FR4 Return | | X | | X | | |
| FR5 Earn | X | | X | | X | |
| FR6 Know | | | X | X | X | X |

Lower-triangular, so **decoupled**: set the DPs in that order and each FR can be tuned
without disturbing the ones above it. It will never be diagonal; discoverability depends on
content, and measurement depends on everything, which is the right shape for an
instrumentation layer.

## What changed to get here (2026-11-28)

1. **FR3 redefined** as "feed data is current and valid". Validity belongs to DP3, where
   `scripts/validate-feeds.py` already gates every rebuild. FR2 now covers editorial pages
   only. Before this, accuracy on data pages and on editorial pages were one FR served by
   two DPs, which is a coupling by definition.
2. **Sitemap and llms.txt moved out of the worker.** Both were embedded in the worker and
   only changed on `npm run deploy:seo`, so a Pages push could ship a page whose sitemap
   entry waited for a second, manual pipeline (FR1 and FR3 coupled through DP1). Now
   `sitemap.xml` is regenerated by the pre-commit hook whenever a commit touches an `.html`
   file, `llms.txt` is a hand-edited file in the repo root, and the worker passes both
   through to the Pages origin. One push satisfies both.

Falsifiable test for change 2: add a page, commit, push. The live `/sitemap.xml` lists it
after the Pages deploy with no other command, and the response carries
`x-seo-source: origin`.

## Standing rule

A new mechanism goes in the row of the FR it serves. If it would put an X **above** the
diagonal, either reorder the DPs (fine if no cycle appears) or split the FR; don't ship the
coupling and patch around it later.
